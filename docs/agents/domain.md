# Domain Docs

This repo uses a single-context layout: `GLOSSARY.md` at the root and ADRs under `docs/adr/`.

Before exploring the codebase, read the glossary if present and any ADRs relevant to the work. If these files do not exist, proceed silently. Domain-modeling creates them when terminology or decisions are resolved.

Use the glossary's terms in issues, proposals, hypotheses, and tests. If a needed term is missing, reconsider whether it matches the project or note the gap for domain-modeling.

If a proposal contradicts an ADR, identify that conflict and explain why the decision should be reopened.
